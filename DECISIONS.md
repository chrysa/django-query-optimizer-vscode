## D-LOCAL-001 — The extension is a SARIF viewer, not an analyzer (FACT)

- **Decision.** All ORM analysis is done by the external `django-query-optimizer`
  Python package; this extension only reads its SARIF output and renders
  diagnostics.
- **Evidence.** `ARCHITECTURE.md`; `src/extension.ts` header; `README.md`.
- **Consequence.** No analysis logic, no Django/Python runtime dependency at
  extension runtime; the producer is versioned separately (`0.1.0+`).

## D-LOCAL-002 — SARIF parsing is a pure, VS-Code-free function (FACT)

- **Decision.** `parseSarif()` takes JSON + paths and returns findings with no
  `vscode` import, so it is unit-testable without a VS Code host.
- **Evidence.** `test/unit/parseSarif.test.ts`; `README.md`; `REQ-TECH-002`.
- **Consequence.** Fast unit tests; the VS-Code-bound parts (`SarifWatcher`,
  `DiagnosticsHub`) are the only pieces needing the electron test host.

## D-LOCAL-003 — URI resolution never uses `process.cwd()` (FACT)

- **Decision.** Absolute `file://` used as-is; `%SRCROOT%` → workspace root;
  relative → SARIF file directory.
- **Evidence.** URI-resolution block in `src/extension.ts`; `ARCHITECTURE.md`.
- **Rationale.** Correct file targeting regardless of where VS Code was launched.

## D-LOCAL-004 — Activation gated on `workspaceContains:**/*.sarif` (FACT)

- **Decision.** The extension activates only when the workspace contains a SARIF
  file.
- **Evidence.** `activationEvents` in `package.json`.
- **Consequence.** No cost for non-Django/non-SARIF workspaces.

## D-LOCAL-005 — CI runs tests + Sonar only; lint lives in pre-commit (FACT)

- **Decision.** ESLint/tsc/pre-commit are not re-run per-push in CI; only tests +
  Sonar gate PRs, with lint replayed at release time.
- **Evidence.** `.github/workflows/ci.yml` header comment.
- **Rationale (stated).** Billing parity with `ci-python.yml`.
